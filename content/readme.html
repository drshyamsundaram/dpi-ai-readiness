ReadMe

A 40-item self-assessment that shows how ready a country is to adopt AI at national scale, using India's digital public infrastructure (DPI) journey as the reference case.

What this tool is

It supports the session "Preparing a country for AI scale". The session explores DPI, trusted data ecosystems, identity and consent frameworks, compute, talent, regulatory readiness and public-private collaboration. Each participant scores their country before the session. The scores are then compared with a reference baseline (this build: {{COUNTRY}}) and pooled across the group.

The eight pillars

P1–P3 are the rails India built for DPI. P4–P6 are what AI adds on top. P7–P8 decide whether the whole system is trusted and used. Each pillar has five questions.

Anchored responses

Each question has written descriptions for scores 1, 3 and 5, and 2 and 4 sit between them. This way, two respondents who choose a 3 mean the same thing. DK (don't know) is allowed and is not scored. If a pillar has two or more DK answers, it is reported as having insufficient evidence.

How the {{COUNTRY}} baseline was assumed (suggestive)

  1. Evidence scan. Public material on each pillar, as of . The sources for this build are listed in the References tab.
  2. Same anchors as respondents. Each item is scored 1–5 against the same written descriptions respondents use.
  3. Factored pillar scores. A pillar's baseline is the mean of its five item scores, computed at build time, so the two can never disagree.
  4. Scoring rules: score what operates at national scale today, not what has been announced; score the national picture, not the best state or sector; where a law exists but its obligations are not yet in force, score at most 3.
  5. Range. Each pillar has a plausible low–high range that shows how far a well-informed reviewer could reasonably move the score.

Baselines in this project

Each baseline is a file in config/baselines/. The same questions are compared against whichever country you choose at build time.

Baselines are suggestive, not definitive. They are expert judgements, not survey results or official positions, and they go out of date as policies and infrastructure change. Use them as reference points to argue with, not verdicts. Facilitators can adjust them for each assessment, for example by updating the evidence, using an expert panel's median scores, narrowing the scope to a state or sector, or setting target scores instead of a peer country. Each baseline is a file in config/baselines/, and the project README explains how to change it.

How scores are computed

  • Pillar score = mean of non-DK items (blank if two or more items are DK).
  • Overall score = mean of the eight pillar scores.
  • Gap = your score − {{COUNTRY}} baseline.
  • Group score = median across respondents. Spread = interquartile range (Q3 − Q1). A spread above 1.0 marks a pillar where respondents disagree.

Your data

Everything runs in your browser. Answers are saved only in this browser's local storage, and nothing is sent to any server. To share results, export a JSON or CSV file from the Results tab. To clear your answers, use Reset my answers on the Start tab.

Customising and contributing

Questions, baseline scores, references and author details all live in JSON config files. Edit them and rebuild to make your own version. The source is in the project repository.
